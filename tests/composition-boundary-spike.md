# #109 toy parser-boundary evidence

`composition-boundary-spike.test.ts` calls the public `parseKaladaV1Expression` on the **whole** scanned interior. The test-only toy host takes an explicit UTF-16 opening offset for `@expr{`, owns `{`, `}`, and the required `|` return marker, and owns all remaining host text. A bounded UTF-16 scanner shields double-quoted strings (including escapes), tracks parentheses, rejects comment introducers and inner braces, and hands only the candidate interior to Expressions. No bracket handling is needed: Expressions v1 diagnoses `[` and `]` as unsupported forms. The guest parser's diagnostics, expression, source and EOF are checked before host spans can be emitted. Each published span is a half-open UTF-16 offset into the parent source.

This proves only the admitted toy protocol, not CF01 completion, generalized delimiter recovery or child-owned lexical handoff. An ambiguous extra `}` before `|`, missing return marker, unsupported comment/brace handoff, malformed or incomplete expression, or exhausted scan emits **no spans**. The scanner cannot safely decide arbitrary child-owned lexical forms or host syntax; this limitation should inform #107 review and #108 design. #108 remains blocked pending #107 review and its own executable evidence; no Formbar approval is inferred.
